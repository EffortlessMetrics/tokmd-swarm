`tokmd` turns a repository or pull request into stable Markdown and JSON that
humans, CI, and coding agents can consume without guessing what was measured.
Use it to inspect a codebase, generate a bounded PR evidence packet, review a
change, or prepare an agent handoff. The same contracts are available from the
CLI, GitHub Action, native bindings, and a deliberately narrower browser/WASM
surface.

## Install and get a useful result

```bash
cargo install tokmd --locked

tokmd --version
tokmd --top 8 --files
```

The summary command is the shortest path from a checkout to a readable view of
its language mix. See [Install and try tokmd](docs/install-and-try.md) for the
first-hour walkthrough, or [Install tokmd](docs/install.md) for release
binaries, Nix, and CI installation paths.

## Choose a job

| Job | Start here | Primary artifact |
| :-- | :--------- | :--------------- |
| Inspect a repository | `tokmd`, `tokmd module`, `tokmd analyze` | Markdown or JSON summary |
| Review a pull request | `tokmd cockpit`, `tokmd packet generate` | `.tokmd/review/` or `sensors/tokmd/` |
| Produce CI/agent evidence | GitHub Action `mode: packet`, `tokmd sensor`, `tokmd gate` | Versioned receipts and manifest |
| Prepare a coding-agent handoff | `tokmd context`, `tokmd handoff` | Bounded bundle and `.handoff/` directory |

For the command-to-artifact reading order, meaning, non-meaning, and next step
for each job, use [User paths](docs/user-paths.md). For copy-ready command
sequences, use [Copy-Ready Workflows](docs/workflows.md).

## First-hour commands

```bash
# Inspect repository structure as JSON
tokmd module --format json .

# Generate one machine-consumable PR evidence packet
tokmd packet generate \
  --base origin/main \
  --head HEAD \
  --output-dir sensors/tokmd \
  .

# Generate the human-oriented PR review packet
tokmd cockpit \
  --base origin/main \
  --head HEAD \
  --review-packet-dir .tokmd/review

# Prepare a bounded coding-agent handoff
tokmd handoff . \
  --preset risk \
  --budget 128k \
  --strategy spread \
  --output-dir .handoff
```

Start with:

- `sensors/tokmd/manifest.json` for packet status and artifact inventory;
- `.tokmd/review/review-map.md` for review order and reproduction commands;
- `.handoff/` for the bounded work order and code bundle.

A complete packet is evidence, not an automatic merge verdict. Optional syntax,
AST, proof, mutation, and coverage signals remain advisory unless a downstream
policy explicitly promotes them.

## GitHub Action

Use the root Action when you want the same packet contract in CI without
installing Rust in the workflow:

```yaml
- uses: EffortlessMetrics/tokmd@v1
  with:
    mode: packet
    paths: .
    artifact: 'true'
    comment: 'false'
```

Released Action refs carry an exact default binary version. Omit `version` for
ordinary adoption; specify one when selecting a release candidate, rolling
back, or choosing a separately verified concrete container tag.

For a complete workflow, see [GitHub Action quickstart](docs/action-quickstart.md).
For every mode, input, output, artifact, checkout requirement, and runtime
boundary, see [GitHub Action reference](docs/github-action.md).

## Review a PR

For local PR review, generate a cockpit packet instead of starting from raw CI
logs or unstructured JSON:

```bash
tokmd cockpit \
  --base origin/main \
  --head HEAD \
  --review-packet-dir .tokmd/review
```

Read the packet in this order:

1. `.tokmd/review/review-map.md` — review order and reproduction commands;
2. `.tokmd/review/comment.md` — concise PR summary;
3. `.tokmd/review/evidence.json` — evidence availability and state;
4. `.tokmd/review/manifest.json` — hash-indexed packet inventory.

In a tokmd contributor checkout, verify the packet before treating it as review
evidence:

```bash
cargo xtask review-packet-check --dir .tokmd/review
```

If a PR changes source-of-truth docs, plans, ADRs, templates, `.jules/goals/**`,
or documentation policy, import the documentation-control receipt:

```bash
cargo xtask doc-artifacts --check --json target/docs/doc-artifacts-check.json

tokmd cockpit \
  --base origin/main \
  --head HEAD \
  --doc-artifacts-check target/docs/doc-artifacts-check.json \
  --review-packet-dir .tokmd/review
```

This exposes documentation-control evidence in the packet; it does not turn
cockpit into a merge decision or promote advisory proof. See
[tokmd in Cockpit](docs/tokmd-in-cockpit.md) for hosted artifacts, proof imports,
and verification boundaries.

## What tokmd produces

| Surface | Output |
| :------ | :----- |
| Repository inspection | Language, module, and file summaries in Markdown, TSV, JSON, JSONL, or CSV |
| Analysis | Risk, effort, complexity, duplication, git, and API-surface reports |
| PR evidence | Cockpit review packet and `sensors/tokmd/` evidence packet |
| Policy and baselines | Gate verdicts, ratchet-ready baselines, and sensor envelopes |
| Agent context | Bounded context bundles and handoff directories |
| Other receipts | CycloneDX, HTML, SVG, Mermaid, badges, and tool definitions |

Use the [artifact glossary](docs/artifacts.md) for receipt names and the full
[CLI reference](docs/reference-cli.md) for every command and option.

## Why it exists

Raw line counts and pasted terminal output are easy to produce and hard to
reuse. Review workflows need stable before/after surfaces. CI needs receipts and
explicit status. Coding agents need bounded context and reproducible evidence
instead of an unstructured transcript.

`tokmd` makes repository shape repeatable, diffable, and machine-readable. In
the wider Effortless Metrics stack, tokmd remains a focused evidence producer;
`evidencebus` can inventory and carry its output alongside other sensors without
turning tokmd into the entire backplane.

## Browser and WASM

`tokmd-wasm` and `web/runner` expose a narrower browser-safe slice:

- `lang`;
- `module`;
- `export`;
- browser-safe `analyze` presets over ordered in-memory inputs;
- archive/ZIP ingestion only when the released bundle and capability receipt
  prove that feature.

Native filesystem flows, Git-history enrichers, `gate`, `cockpit`, `sensor`,
`evidence-packet`, `baseline`, `context`, and `handoff` remain native-first.
The browser runner supports local files/directories, progress, bounded GitHub
ingest, retry/rate-limit guidance, and session-only GitHub tokens without
putting raw tokens in cache keys.

The machine-readable capability contract lives in
[`docs/capabilities/wasm.json`](docs/capabilities/wasm.json). See
[Browser runner](docs/browser.md) and
[Browser capability matrix](docs/browser-capability-matrix.md) for the current
shipped, experimental, and native-only boundaries.

## What tokmd is not

- It is not a formatter, linter, or build system.
- It is not a developer-scoring tool.
- It is not a vulnerability database or SAST replacement.
- It does not prove the absence of undefined behavior or memory-safety defects.
- It does not ask you to trust prose where a receipt can be emitted instead.
