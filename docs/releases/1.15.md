# tokmd 1.15

Status: `v1.15.0-rc.2` was published and rejected by exact-artifact browser
consumer proof. The focused browser control-state fix is merged and has been
imported through the history-preserving publication path; both repositories are
aligned at `b15f85ffef5023216888ffa4c7e7f42acf8a9398`. The next candidate is
`v1.15.0-rc.3`. Stable release remains pending the complete RC3 consumer
matrix.

## Release thesis

tokmd 1.15 makes repository evidence portable, consumable, and easier to
operate. It improves CLI configuration, progress, help, recovery, and argument
consistency; adds deterministic snapshot and fail-closed ZIP ingestion across
native and browser/WASM paths; strengthens packet consumption for review
workflows; and makes the Action/container path reproducible and version-safe.

## User-facing capabilities

### CLI and configuration UX

- Root options are either genuinely shared or rejected clearly; they are not
  parsed and silently ignored.
- Scan options work in the documented positions, generated help covers every
  command, typo suggestions use the live command inventory, and output flags
  use canonical `--output` and `--output-dir` spellings with compatibility
  aliases.
- `--show-config`, progress routing, and per-preset help make the first useful
  command easier to understand and reproduce.

### Portable repository evidence

- `RepoSnapshot` and ordered in-memory input paths let native, binding, and
  browser/WASM consumers operate over the same deterministic repository model.
- Archive/ZIP admission is bounded and fail-closed rather than extracting
  untrusted paths into a working tree.
- Native and archive-backed scans preserve path normalization, redaction, root
  stripping, ordering, and receipt parity.

### Browser and WASM

- The release workflow builds the archive-enabled WASM artifact rather than an
  analysis-only substitute.
- Browser capability reporting distinguishes available archive ingestion from
  native-only filesystem and Git-history work.
- ZIP controls refresh after the worker reports `zipball: true`, so the user
  interface and the exact released bundle expose the same capability.
- Browser support remains deliberately narrower than native tokmd; capability
  receipts, not source-code presence alone, define the supported surface.

### Packets and review consumption

- Packet generation and ub-review consumption expose deterministic manifests,
  artifact inventories, status, warnings, errors, reproduction commands, and
  bounded non-claims.
- Review packets give humans and agents a stable reading order instead of
  requiring them to interpret raw CI logs or scrape prose.
- Optional syntax, shadow, proof, mutation, and coverage evidence remains
  visible as advisory, missing, stale, degraded, skipped, or unavailable rather
  than silently becoming a pass.

### GitHub Action and container runtime

- Released Action refs carry an exact default binary version; explicit
  `version` remains available for RC selection, rollback, and verified pins.
- `mode: packet` produces the same `sensors/tokmd/` contract used by local and
  downstream review workflows.
- Container execution accepts only verified concrete tags. Candidate images are
  exercised by anonymous pull, exact version, and mounted-packet proof before
  their immutable digest is promoted to the release tag.
- Mutable Action and GHCR aliases move only after stable exact-artifact,
  publication, and consumer gates pass.

### Evidence and review signals

Syntax, AST-shadow, and review-priority evidence is more useful and better
documented, but remains advisory unless a downstream policy explicitly
promotes it. The release does not turn parser signals into a safety verifier or
an automatic merge decision.

## Adoption examples

Inspect a repository:

```text
tokmd --show-config
tokmd module --format json .
```

Generate a bounded PR evidence packet:

```text
tokmd packet generate \
  --base origin/main \
  --head HEAD \
  --output-dir sensors/tokmd \
  .
```

Use the Action after checking out full history:

```yaml
- uses: actions/checkout@v6
  with:
    fetch-depth: 0

- uses: EffortlessMetrics/tokmd@v1
  with:
    mode: packet
    paths: .
    artifact: 'true'
    comment: 'false'
```

Use an explicit `version` only when selecting an RC, demonstrating rollback,
or selecting a separately verified concrete container tag.

## Release-candidate history

### RC1

`v1.15.0-rc.1` proved the native binaries, Action/container paths, Nix,
checksums, and attestations, but exact consumer proof rejected the browser
artifact because the published WASM archive was analysis-only and did not carry
ZIP ingestion.

### RC2

`v1.15.0-rc.2` corrected the release artifact to include archive support. The
exact tagged browser smoke then exposed a separate product defect: the worker
reported `zipball: true`, while the ZIP input and load button stayed disabled
because repository-load controls were not refreshed after worker readiness.

That defect is fixed and imported through publication. Because it changes
shipped browser behavior, RC2 remains rejected and the fix must be published as
RC3; the existing RC2 tag is not moved.

### RC3 acceptance

RC3 is accepted only when the exact downloaded artifacts pass the complete
consumer workflow, including native binaries, checksums, attestations, Nix,
Action binary/container packet modes, and the released archive-enabled WASM in
a real browser with ZIP controls enabled.

## Non-claims

- tokmd does not prove absence of undefined behavior or memory-safety defects.
- tokmd does not make an automatic merge verdict.
- AST, syntax, mutation, coverage, and proof evidence are not promoted by
  default.
- Homebrew, AUR, Scoop, and WinGet prototype files are not supported 1.15
  distribution channels.
- No container tag is supported before its exact candidate and anonymous
  runtime verification receipts pass.
- A source build or local browser test is not a substitute for consuming the
  exact released artifact.
